# UI-005：战斗 HUD、单位信息面板与 UI 阶段集成验收

## 角色

你是本 Unity 项目的 HUD 表现、信息面板和 UI 阶段集成 Agent。

你的职责是在 UI-001～004 已完成的数据和流程上，实现 `UI_SPEC.md` 中已经确认的正式 HUD 结构，把可用字段绑定到真实状态，并对“自动加载 → 准备 → 手动部署/撤退 → 战斗 → 返回准备”的完整本地循环进行最终编译、PlayMode、Player 和人工视觉验收。

本任务中的 UI 仍然只是表现和命令入口。不得为填满面板而发明赤金、玩家生命、技能、阵营、种族或设置菜单规则。

## 任务背景

UI-001～004 应已经形成可用闭环，但正式 HUD 仍不完整。`UI_SPEC.md` 已明确待部署槽、右侧资源区、设置按钮、顶部状态栏、左侧单位信息面板和世界撤退入口的主要比例、Sprite 来源与层级。仍未确认的内容包括赤金数值、玩家生命规则、设置菜单功能、页签实际内容、基础属性图标映射、字体和部分精确偏移。

本任务必须区分“已有真实数据可绑定”和“只有视觉插槽但业务未定义”。真实字段需要实时更新；未定义字段要显示明确的未接入状态或保持禁用，不能用任意常数制造完成感。

当前 BattleDemo 调试 UI 仍需保留组合键入口，用于查看 input/event/result digest，但它不能默认覆盖正式 HUD，也不能绕过 UI-004 的正式运行时输入。

## 本任务目标

1. 完成 UI_SPEC 中已确认的正式 HUD 层级、比例、Sprite 和阶段显隐关系。
2. 完成右侧 Deployment Cost 与赤金区域：Cost 绑定 PlayerState；赤金只建立明确未接入的显示位，不发明数值。
3. 完成顶部 BattleStatusPanel：Preparation 显示固定对手文字和 30 秒倒计时；Battle 显示初始敌人击败进度、战斗状态和玩家生命未接入位。
4. 完成左上 SettingsButton 的视觉和点击区域拟合；设置菜单未确认时保持禁用或只输出明确“未接入”反馈。
5. 完成 UnitInformationPanel 外壳、上下背景、血条和选择路由，显示当前可可靠取得的头像、精英化、类型/名称、当前 HP/最大 HP。
6. 建立待部署己方、已部署己方和战斗敌方的统一选择快照；查看敌人不能获得己方部署/撤退权限。
7. 建立技能/阵营/种族三个页签外壳，不自行填充未确认内容或图标映射。
8. 对时钟图标制作最小派生透明资源或等价运行时材质处理，保留源图不变。
9. 建立可从命令行自动运行的 UI 截图套件，自动构造关键状态、固定分辨率截图并输出对应布局/状态清单。
10. Agent 必须实际读取参考图与自动截图，结合数值清单进行视觉判断；发现可归因偏差时修正并复拍，不能只生成图片而不审查。
11. 在 1920×1080 下参照图1～图6完成第一轮视觉拟合，并检查至少一个其他 16:9 分辨率和一个非 16:9 分辨率的退化情况。
12. 执行最终 Editor 编译、相关 EditMode/PlayMode、Windows Standalone 构建/运行和完整人工流程；更新 ARCHITECTURE、TEST_PLAN 和任务表真实状态。

## 已确认规则

- 正式 UI 使用 `1920×1080` 为参考分辨率，主要比例和换算以 UI_SPEC 为准。
- 大部分正式 UI Sprite 来自 `SpriteAtlasTexture-UI_BATTLE...Merged` 已命名切片；不得重新解释原作中未确认功能。
- Deployment Cost 是真实玩家资源，初始为 99，阶段切换不重置；UI 实时显示当前可用值。
- 赤金与 Cost 独立；当前没有赤金初始值或变化规则。
- 顶部状态栏位于屏幕上方中央，背景自带三格分隔。
- Preparation 左格显示下一场对手纯文字；Battle 左格显示已击败初始敌人数/本场初始敌人总数。
- Preparation 中间显示 30 秒倒计时；各后续阶段的独立倒计时尚未确认。
- 玩家生命初始值和扣除规则尚未确认。
- UnitInformationPanel 位于左侧、铺满高度，渲染层级在设置按钮、顶部状态栏和待部署槽之下。
- 待部署己方、部署区己方和战场敌方都可显示信息面板；敌方只可查看。
- 信息面板血条只显示生命，不显示护盾；填充从左到右，数字为 `CurrentHP / MaxHP` 并随填充右端移动。
- 下半部分页签名称为技能、阵营、种族；具体内容、图标、默认页和颜色尚未确认。
- SettingsButton 使用 `SettingsButtonIcon`；贴图有阴影，位置按可见主体拟合。
- BattleDemoUI 默认隐藏，通过组合键显示；正式 HUD 不依赖调试面板。

## 实施要求

### A. HUD 层级与统一数据绑定

1. 先检查 UI-002 正式 HUD 根、CanvasScaler、sorting order 和 UI-004 阶段接口，不新建第二套重叠 Canvas/PlayerState。
2. 建立只读 HUD ViewModel 或等价适配层，统一提供：当前阶段、Preparation 剩余时间、Player Cost、对手标识、当前 Battle 初始敌人数/已击败数、winner/reason、当前单位选择。
3. HUD 不直接遍历 BattleRunner 或重新计算事件。敌人数和选中单位当前 HP 来自 UI-004/Presentation 已消费事件或明确的只读状态。
4. 所有订阅在 OnDisable/OnDestroy/场景重载时解除；同一状态重复应用不得重复创建子物体或监听。

### B. 右侧资源区域

5. 保留 UI-002 已实现的 DeploymentCostPanel，核对 UI_SPEC 第 6 节的 `180×80`、右下锚定、底边 220、图标中心和缩放公式。
6. Cost 文本绑定真实 PlayerState，部署/撤退/自动部署后同帧或下一次 UI 刷新可观察更新，不自行加减字符串。
7. 建立紧邻上方的 GoldCurrencyPanel，使用 `ResourcePanelBackground` 和 `round_sources_icon.png`，数字为黄色。
8. 因赤金数据尚未定义，数字位置显示明确未接入状态（建议 `--`）或保持数值控件禁用；不得创建 PlayerState.gold=0 并宣称规则已实现。最终选择和视觉结果写入报告。

### C. 顶部 BattleStatusPanel

9. 使用 `BattleStatusPanelBackground`，按 UI_SPEC 的顶部居中比例建立 830×54 参考区域，不重复绘制已有三格分隔。
10. Preparation 左格隐藏敌人数图标，显示固定测试对手的现有 `playerId` 或 UI-004 已提供的对手显示字段。该字段只是当前测试数据标识，不擅自创建昵称/头像规则。
11. Battle 左格显示 `defeatedInitialEnemies / totalInitialEnemies` 并使用 `BattleStatusPanelEnemyCountIcon`。分母在本场输入封存时确定，只统计初始敌方 Deployed；分子只随这些 unit ID 的 Death 事件增加，重复事件/Replay 必须重置并保持一致。
12. Preparation 中格显示时钟图标和剩余时间。未确认格式时使用稳定、可本地化替换的临时格式，例如向上取整的整数秒；在报告中明确它是 UI 格式选择，不改变真实 30 秒时钟。
13. Battle 中没有已确认的独立倒计时；显示明确阶段文字或现有播放状态，不把 Tick/20 伪装成倒计时。
14. 右格使用 `BattleStatusPanelPlayerHealthIcon`。玩家生命数据尚未定义，显示 `--` 或禁用数值控件；不得硬编码生命值。
15. 战斗完成并回 Preparation 后，左格恢复对手文字、敌人数归零/隐藏，中格恢复新一轮 30 秒。

### D. 时钟派生资源

16. 保留 `SpriteAtlasTexture-CHARACTER_SORT_TYPE_ICON...` 源图和 `.meta` 不变。
17. 只针对当前 Clock 切片生成最小派生透明图：由亮度生成 Alpha、黑色背景透明，前景通过 UI Color 或派生像素呈灰色。不得普通 RGB 反色后保留黑底。
18. 检查边缘抗锯齿和状态栏背景可读性。除非证明确有相同需求，不处理整张图或其他切片。
19. 记录派生资源的生成方式和可重复步骤；不得使用外部上传服务或未按本提示词工具规则审查、记录和冒烟的工具。

### E. SettingsButton

20. 使用 `SettingsButtonIcon` 锚定屏幕左上角。以可见主体而非完整透明矩形拟合图1～图4，保证阴影不被裁切。
21. 确定并记录最终 RectTransform、显示尺寸和点击区域。
22. 设置菜单功能未确认：按钮可保持禁用，或点击只输出结构化 `settings.notImplemented` 并不改变游戏状态；不得临时拼出设置菜单。

### F. UnitInformationPanel

23. 面板未选单位时隐藏；选中待部署己方、部署己方或可查看的战斗敌方时显示并更新同一面板。
24. 面板宽约屏幕高 `2/3`、高度满屏，上下区域 `21/40 + 19/40`，背景使用 `UnitInformationPanelUpperBackground/LowerBackground`；层级位于设置按钮、顶部状态栏和待部署区之后。
25. 上半部分只显示当前可靠字段：真实头像、已知精英化、单位名称/type ID 和能从目录/当前选择取得的基础信息。不得根据参考作品补职业、信赖、潜能或其他未定义字段。
26. 对战斗敌方若 BattleInput 未携带实例精英化，显示明确未知/不显示，不得把 Rarity 或类型初始值伪装为该实例当前精英化。
27. 血条按 UI_SPEC 建立 556×12 参考尺寸，顶边在 1920×1080 的 y=490；当前 HP 从左填充，不显示护盾，数字 `CurrentHP / MaxHP` 跟随填充右端。数值 clamp 只防止 UI 越界，不改变权威 HP。
28. 准备阶段玩家单位没有战斗损伤时可显示类型 MaxHP/MaxHP；战斗单位使用 Presentation 当前状态。选择死亡视图后的保留/隐藏行为若现有 Presentation 不支持，不新增战斗规则，记录为未验证。
29. 建立技能、阵营、种族三个页签外壳。若默认页、颜色和内容仍未确认，先在实现前向用户确认；未得到答复不得把参考作品内容或任意图标映射写成正式行为。
30. 查看敌方只更新面板，不显示撤退按钮、不允许部署/移动命令。

### G. 选择路由和阶段切换

31. 统一选择状态以稳定 unit ID + 来源区域/战斗侧标识，不用当前 GameObject 引用作为唯一身份。
32. 待部署槽选择沿用 UI-002；准备阶段已部署选择沿用 UI-003；战斗敌方选择通过只读 Presentation view 映射加入，不修改事件或 Core。
33. 阶段切换、单位移除、Replay 或视图销毁时验证当前选择仍有效；无效则隐藏面板并清理引用。
34. Home/Away 调试观察视角变化时，敌我颜色和可操作权限仍以当前本地玩家身份为准，不因画面旋转反向授权撤退。

    - Preparation、10 槽、未选中；

41. `ScreenCapture.CaptureScreenshot` 或等价截图写盘是异步的，退出 Editor/Player 前必须确认文件存在、可解码、尺寸正确且不是全黑、全透明或单色空帧。

- 赤金和玩家生命在无数据时处于明确未接入状态，不显示任意业务数值；
- 选择 staging/deployed/enemy 时信息面板来源和权限正确；
- 信息血条 0、半血、满血的宽度与数字位置；
- 阶段切换/单位销毁后无效选择被清理；

自动截图套件还必须验证：

- 所有规定状态均生成 PNG 和 manifest，文件数、状态名和分辨率相符；

- Agent 已实际读取每张截图并产出逐状态视觉结论；
- 被判定为“需调整”的可归因问题经过修改后有复拍证据，未收敛项明确保留；
- 截图产物位于忽略目录，`Assets` 下没有因此新增截图或 `.meta`。

不要用大量脆弱像素断言代替人工拟合。测试 XML 必须可解析、测试数大于 0、失败为 0才能写通过。

### 人工游戏流程验证

1. 进入 SampleScene，无需 InitButton；
2. 核对待部署槽、Cost=99、赤金未接入位、顶部对手和 30 秒；
