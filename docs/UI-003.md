# UI-003：状态驱动的部署、撤退与世界选择反馈

## 角色

你是本 Unity 项目的准备阶段交互与单位视图 Agent。

你的职责是把现有“从待部署 UI 拖出单位”的原型迁移成状态驱动的完整纵向切片：拖拽期间只操作临时表现，落点成功后由 PlayerState 原子修改单位区域、坐标和 Cost，正式 UI/世界对象再根据新快照刷新；选中部署区单位后可以立即撤回待部署区。

本任务可以最小修改 `SampleScene.unity`、部署交互脚本、准备阶段单位视图和世界选择效果。不得让 Transform、碰撞命中或 GameObject 存在性成为玩家单位状态的权威来源。

## 任务背景

当前 `UnitDeployment` 通过 EventSystem 查找带 `UnitUI` 标签的对象，再从 `ButtonDebug.idMap` 复制一个类型原型。拖拽松开后，它只查 `9×8` 边界和两个门格，用 `GameObject.Find("Block(x,y)")` 吸附对象，不更新玩家单位 ID、区域、待部署堆叠、部署占位或 Cost。失败时通过销毁/隐藏临时对象表达结果。

UI-001 已经把这些规则迁移到 PlayerState 原子操作；UI-002 已经把正式槽位绑定到有序堆叠快照。本任务必须让交互层只选择具体 unit ID、展示拖拽预览并提交命令。命令成功后，准备阶段世界视图和 UI 都从同一玩家快照重建/更新。

准备阶段部署单位和战斗 Presentation 单位属于两个生命周期。前者反映玩家保存阵型，后者反映封存 BattleInput 的单场事件。两者不能共用同一可变对象并相互写回。

## 本任务目标

1. 将正式待部署槽接入拖拽开始、预览、取消和落点提交流程。
2. 从一个堆叠槽稳定选择一个具体单位实例，不再按 type ID 复制临时权威对象。
3. 只允许部署到本地一基 `9×4` 空格，拒绝 `(5,1)` 门格、越界、占位和费用不足。
4. 成功部署后正常扣除 Cost、更新 PlayerState、减少/移除对应待部署堆叠，并创建/更新一个准备阶段单位视图。
5. 失败部署时销毁预览并保持 PlayerState、Cost、槽位和正式世界单位完全不变，同时提供明确诊断。
6. 建立独立的准备阶段世界单位视图根，按 PlayerState 已部署快照创建、绑定、移动和清理真实 DefaultUnit 表现。
7. 支持点击己方已部署单位进行单选，显示世界空间 `DeployedUnitSelectionOverlay` 和 `ReturnToStagingButtonIcon`。
8. 点击撤退按钮后不二次确认，调用 PlayerState 原子撤退；成功返还 100% Cost 并恢复严格堆叠，失败保持状态。
9. 为 UI-004 预留明确的交互启用/禁用接口，使阶段切换能锁定所有部署/撤退输入。
10. 建立领域命令回归和最小 PlayMode 拖拽/撤退冒烟，不对精确美术位置做脆弱像素断言。

## 已确认规则

- 玩家本地部署区是 `9×4` 一基坐标，`x=1..9`、`y=1..4`。
- 蓝门 `(5,1)` 不可部署；一格大小为 1 米，即 100 Unity 世界坐标单位。
- 部署区同一坐标只能有一个单位。
- 从待部署区部署到空格时，在操作提交时检查当前 Cost；费用足够才成功并扣除单位部署 Cost。
- 费用不足不禁止玩家开始拖拽，但落点提交失败且玩家状态不变。
- 当前任务不实现目标格已有单位时的替换预览；该情况返回明确“不支持/占用”结果。
- 从严格堆叠槽部署只取出一个独立单位实例，其他成员继续留在同一槽。
- 撤退按钮点击后不需要二次确认。
- 撤退需要检查返回后的严格堆叠和 13 槽容量；成功后返还 100% 部署费用，失败无状态变化。
- 部署区不堆叠单位。
- 世界选择菱形使用原始 `DeployedUnitSelectionOverlay`，原图已是菱形，不再旋转 45°。
- 撤退图标位于菱形左上边中点附近，精确视觉偏移需要场景拟合。
- 选择效果是世界空间表现对象，不属于屏幕空间 Canvas，也不改变权威状态。
- UI 和准备阶段 GameObject 只投影 PlayerState。

## 不属于本任务的内容

- 不实现两个部署区单位交换位置；
- 不实现自动部署、Overflow 清理、30 秒时钟或战斗启动；
- 不实现商店、赤金、玩家生命、技能或 Buff 效果；

- 不把准备阶段拖拽接入 Unity Physics 作为权威碰撞；Physics/Raycast 只可用于输入命中和视觉交互；
- 不修改 TASK-007 血条公式或护盾机制；
- 不整体重做地图、相机、DefaultUnit 或渲染管线；

## 实施要求

### A. 建立明确交互状态

1. 用明确状态表达 Idle、Dragging、SelectedDeployed 等交互阶段，避免由 `_dragInstance != null` 和散落布尔值推断全部业务状态。
2. 拖拽开始时从正式槽快照取得一个稳定 unit ID、type ID 和表现数据；不从 `ButtonDebug.Instance.units/idMap` 查找。
3. 拖拽预览是临时视图，不加入 PlayerState、不占格、不扣 Cost、不加入正式准备单位集合。
4. 右键、Esc、失焦、对象销毁、场景切换或交互锁定都必须安全取消并销毁预览。
5. 提供统一 `SetInteractionEnabled(bool)` 或等价接口。禁用时取消拖拽、清除选择、关闭撤退入口并阻止新输入。

### B. 坐标与落点

6. 先核对 `Block(x,y)` 的实际世界位置和 `UnitDeployment.ConvertCoordinate` 公式。公开提交使用一基 `9×4`；若复用旧换算，不能把零基/一基偏差带入 PlayerState。
7. 世界吸附优先使用明确的场地坐标映射或已验证标记缓存，不在每次落点用 `GameObject.Find` 作为唯一业务验证。
8. 目标合法性至少检查：坐标存在、属于本地 9×4、不是 `(5,1)`、PlayerState 未占用、单位仍在 Staging、类型存在、当前 Cost 足够。
9. UI 射线命中只决定拖拽来源，世界射线/平面交点只产生候选坐标；最终成功必须来自 PlayerState 命令结果。
10. 预览可以按候选格显示合法/非法状态，但不得因预览进入合法格提前扣费或修改区域。

### C. 准备阶段世界视图

11. 建立与 `BattleDemoViews` 分离的 `PreparationUnitViews` 或等价根。每个正式视图以稳定 unit ID 绑定一个 PlayerState 已部署实例。
12. 使用现有真实类型目录、DefaultUnit 和 Spine 初始化能力创建视图，不扫描源 JSON，不复制隐藏的场景原型。
13. 创建逻辑可以复用/提取 `MappedBattlePresentationViewFactory` 中的数据驱动资源桥，但不要让准备阶段视图实现战斗事件接口或回写 Battle Core。
14. 状态成功部署后，由视图协调器根据快照创建/定位单位；状态成功撤退或移除后销毁对应准备视图。失败命令不创建或销毁正式视图。
15. 视图 reconcile 必须幂等。同一快照重复应用不重复创建对象；退出场景或进入后续战斗时能一次性隐藏/清理。
16. 保留 `UnitIdentity` 的 type ID，并建立可查的玩家 unit ID 绑定；不得继续用 UnitFactory 的负数临时 ID。

### D. 部署提交和反馈

17. 左键松开时只提交一次部署命令。成功后销毁预览，由状态刷新生成正式视图；不得把预览直接“升级”为权威对象而跳过状态。
18. 成功可观察摘要至少包含 unit ID、type ID、from/to、坐标、Cost before/after 和槽数量 before/after。
19. 失败摘要包含稳定错误码和候选坐标；禁止吞异常、只隐藏对象或打印“失败”而没有原因。
20. Cost 面板和待部署槽通过 PlayerState 变化刷新，不能由部署控制器直接减文本或手工删除槽。

### E. 已部署选择和撤退

21. 点击己方准备阶段部署视图进行单选；点击另一个单位转移选择；点击空白或交互禁用清除选择。敌方/战斗视图不获得撤退权限。
22. 建立独立世界选择效果，使用 `DeployedUnitSelectionOverlay` 原方向。以单位上方约 200 世界单位作为初始拟合值，但先确认当前相机和单位平面中“上方”对应的轴。
23. `ReturnToStagingButtonIcon` 作为同一组世界表现，初始锚定菱形左上边几何中点；对带阴影可见主体进行人工微调。
24. 世界按钮可用 Collider/Raycast 或等价输入桥接，但点击只调用 PlayerState `TryRetreat`；不得直接 Destroy 正式视图、改变坐标或加 Cost。
25. 撤退成功后状态事件驱动正式视图销毁、槽恢复/合并和 Cost 更新。撤退失败保留单位及选择效果，并显示结构化原因；不需要二次确认。
26. 选择效果的渲染排序使用局部 Sorting Layer/order、Renderer 设置或局部材质解决。若必须修改全局 URP/GraphicsSettings/地图材质，停止询问。

### F. 生命周期和收尾

27. 检查所有事件订阅、静态 Instance、输入状态、临时对象和视图映射在 OnDisable/OnDestroy/场景重载时清理。
28. 旧 `UnitDeployment` 可以保留为 legacy/debug 或由新组件替代场景引用，但不得同时有两套控制器响应同一次鼠标输入。
29. 场景修改采用幂等接线并审查序列化 diff，避免触碰 BattleDemoRoot、地图、相机和无关 RectTransform。
30. 更新文档只描述实际完成的状态驱动链。

在 UI-001 领域测试基础上至少覆盖：

- 从多成员堆叠开始拖拽只选择一个稳定 unit ID；
- 拖拽开始/移动/取消不改变 PlayerState；
