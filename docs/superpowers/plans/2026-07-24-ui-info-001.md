# UI-INFO-001 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Complete the UnitInformationPanel upper section for staging, deployed, and battle-enemy selection with real read-only battle data.

**Architecture:** PlayerState owns persistent units; the sealer converts local and independent opponent states into sealed BattleInput instances that retain elite metadata. A pure UnitDetailResolver creates immutable detail snapshots from PlayerState+catalog or sealed BattleInput+Presentation state. FormalBattleHudUi005 reads only those snapshots.

**Tech Stack:** Unity 2022.3.62f1, C#, Unity Test Framework, UGUI, Player-safe Resources.

## Global Constraints

- No Battle Core behavior, coordinate mapping, winner rules, Package/ProjectSettings, image pixel, Sprite slice, Sprite ID, or GUID changes.
- Elite is presentation metadata only; it never changes combat results.
- HUD does not read source JSON or display resource keys as names.
- Nonempty Buffs without resolved attributes show `--` for all six dynamic fields.
- The opponent is a read-only fixture, not a player clone, network model, or command target.

private static bool TryValidateUniqueUnitIds(PlayerStateSnapshot home, PlayerStateSnapshot away, out string error)
{
    foreach (var id in home.Units.Select(unit => unit.UnitId))
        if (away.Units.Any(unit => string.Equals(unit.UnitId, id, StringComparison.Ordinal)))
        { error = "player.unitId.conflict; unitId=" + id + "; homePlayerId=" + home.PlayerId + "; awayPlayerId=" + away.PlayerId; return false; }
    error = string.Empty; return true;
}
