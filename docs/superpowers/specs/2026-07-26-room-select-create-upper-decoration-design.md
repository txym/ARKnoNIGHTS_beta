# Room Select 创建区上方内部装饰复刻设计

状态：用户已确认设计方向，等待书面规格复核。

## 目标

以已经通过人工验收的“创建同盟”横条为固定锚点，复刻参考图 9 中该横条上方的内部装饰内容。

本轮只调整创建区上方装饰，不调整加入区，不修改创建或加入房间的 LAN 行为。

## 已冻结基线

在 `1920×1080`、屏幕左上角为原点时，已经验收的创建横条 Rect 保持为：

| 区域 | X | Y | Width | Height |
| --- | ---: | ---: | ---: | ---: |
| 创建同盟横条 | `1154` | `453` | `717` | `99` |

以下内容不得因装饰校准而改变：

- 横条背景的位置、尺寸和拉伸方式；
- 横条内创建图标及“创建同盟”文字的可见边界；
- 横条点击 Rect、层级和 `CreateRequested` 行为；
- 加入区、公共标题、左侧身份区以及 Room 页面；
- 房间发现、房间号预填、创建、加入和局域网通信。

## 验收范围

复刻创建横条上方的内部内容，包括：

- 后方横向放射状 Logo；
- 中央八边形“+”图标；
- 中央左右括号；
- 中央上下的小字和标识条；
- 四个菱形标记。

青色外框线明确排除在本轮复刻和验收范围之外。实现不得为了补足外框而创建新的位图、矢量线或代码生成边框。

## 素材与复用

所有位图继续使用已经导入的 `Assets/Resources/UI/Lobby/Home` Sprite，来源必须是：

`G:\素材\11.14\Unpacked_1763129662\Android\ui\autochess\[uc]autochessouter`

只允许使用不以 `$0` 结尾的普通版本。本轮不新增、重绘或修改任何源贴图，不改变 `.meta` GUID。

| Sprite | 语义 | 预计实例数 |
| --- | --- | ---: |
| `room_select_create_logo` | 后方放射状 Logo | 1 |
| `room_select_create_middleicon` | 中央八边形“+” | 1 |
| `room_select_create_left_line` | 左右括号 | 2 |
| `room_select_create_text_01` | 中央第一行标识 | 1 |
| `room_select_create_text_02` | 中央第二行标识 | 1 |
| `room_select_img_startroom` | 顶部小字标识 | 1 |
| `room_select_dot` | 四周菱形标记 | 4 |

右括号必须复用 `room_select_create_left_line`，并相对左括号旋转 `180°`；不得导入另一张替代贴图。菱形必须复用同一个 `room_select_dot` Sprite。

## 布局与层级

采用“逐贴图可见边界对齐”，不把整个装饰组作为一个统一缩放对象：

1. 以创建横条左上角和横条宽度建立创建区局部坐标。
2. 从归一化为 `1920×1080` 的图 9 测量每个语义元素的可见像素边界。
3. 对源 Sprite 的 Alpha 可见边界进行离线测量，显式补偿透明留白；不以完整 Sprite Rect 的几何中心代替视觉中心。
4. 每个 Sprite 保持自身宽高比，分别设置尺寸和局部位置；禁止用创建区容器的非等比缩放统一“挤”到目标位置。
5. 允许多张素材重叠。推荐从后到前的渲染顺序为：
   - `room_select_create_logo`；
   - 四个 `room_select_dot`；
   - 左右两个 `room_select_create_left_line`；
   - `room_select_create_middleicon`；
   - `room_select_create_text_01`、`room_select_create_text_02`、`room_select_img_startroom`；
   - 已冻结的创建横条。
6. 所有装饰 `Image.raycastTarget=false`，并位于创建横条渲染层之后，不得遮挡横条或拦截点击。

若真实参考层级与上述推荐顺序冲突，以截图中可见的遮挡关系为准，但不得改变横条的冻结层级。

## 代码边界

预计只修改：

- `LanLobbyView` 中创建区装饰节点的构建、复用、旋转和布局；
- 创建区装饰的布局数据或局部常量；
- 对应 EditMode/PlayMode 布局断言；
- 局部截图、差异报告和素材使用报告中与创建区装饰直接相关的部分；
- 必要的 SPEC、TEST_PLAN 或完成报告记录。

不得修改：

- 素材文件内容和导入来源；
- 加入区装饰布局；
- 已验收横条及其内部图标/文字参数；
- LAN 协议、发现、房间号和房间状态逻辑。

## 自动核查

新增独立的 `home-create-decoration` 局部核查，不使用整张 Home 的总差异率决定本轮是否通过。

自动报告至少包含：

- 参考裁剪、实际裁剪、半透明叠加图和差异图；
- 每个主要语义元素的参考可见边界、实际可见边界、中心偏差和宽高偏差；
- 两个括号和四个菱形的实例数量；
- 右括号相对左括号的 `180°` 旋转断言；
- 每个渲染 Sprite 的 Resources 路径、素材库相对路径、SHA-256 和出现次数；
- 创建横条背景、图标和文字的冻结基线复测结果。

可见边界检测在参考和实际截图中使用相同颜色/Alpha 阈值，并对相互重叠的元素使用小范围语义 ROI，避免把相邻青色像素合并为同一组件。

## 通过标准

- 创建横条 Rect、背景、图标和文字相对已验收基线的偏差为 `0 px`；
- 每个主要装饰元素的可见中心在 X、Y 方向偏差均不超过 `1 px`；
- 每个主要装饰元素的可见宽、高偏差均不超过 `2 px`；
- 两个括号和四个菱形的数量、复用关系、旋转和层级符合设计；
- 装饰不拦截创建横条点击，创建及 LAN 房间闭环相关测试无回归；
- 素材报告中不存在 Unpacked `$0` 来源、未登记 Sprite 或新绘制替代位图；
- 真实可见 `-force-d3d11` Windows Player 在 `1920×1080` 生成有效截图；
- 最终仍需人工核查参考裁剪、实际裁剪和叠加图。

如果某个极细小标识因参考图压缩、透明混色或抗锯齿无法被稳定分割，报告必须把该项标为“需人工复核”，不得通过扩大阈值或移动其他元素制造自动通过。

## 停止条件

出现以下情况时停止视觉微调并报告证据：

- 为匹配内部装饰必须移动已验收创建横条；
- 参考图中的内部元素无法由上述批准素材及其重复、旋转、重叠关系解释；
- 需要修改素材文件、重新生成 `.meta` 或使用 `$0` 版本；
- 三次有实质差异的定位尝试后，同一元素仍无法满足自动边界标准。
