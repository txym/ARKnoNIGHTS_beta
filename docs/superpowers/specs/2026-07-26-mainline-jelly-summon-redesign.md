# 基于主分支重做的果冻丁定时召唤能力设计

## 背景与取舍

旧的 `codex/summon-jelly-minions` 分支与当前 `txym` 的战斗、准备阶段和演出架构存在 14 个文本冲突。采用的方案是从当前主分支重新接入同一玩家可见能力，而不是合并或复制旧分支实现。

这保留主分支已经形成的运行时入口、结果投影和 UI 生命周期；旧分支仅用于核对已确认的数据与行为，不能作为代码合并来源。

## 已确认的数据与玩家可见行为

- `5503 / arcslma` 持有能力 `SUMMON_JELLY_MINIONS`；旧 `SPLIT_THREE` 不保留别名。
- 技术 ID 不显示给玩家；能力显示名称允许为空。描述为：`每隔一段时间，分裂出三个<果冻丁>。`
- 技力恢复规则是全局规则：所有采用自动恢复的技能各自保存当前技力，但统一按每秒 `2` 点恢复。它不是 `5503` 的专属数值。
- 本能力初始技力为 `5`，需求为 `15`。在当前 20 TPS 战斗时钟下，首次施放为 Tick `100`（5 秒）；施放并扣除技力后，下一次为 Tick `250`（再过 150 Tick / 7.5 秒）。
- 每次施放生成 3 个 `5504 / arcslmi / 果冻丁`。`5504` 保持已确认的基础数据与 `UnitSkelType2` 资源映射；它没有该能力，不能递归召唤。
- 生成位置在施法者当前位置中心、边长 1m 的正方形内确定性采样。1m × 1m 正好是地图一个格子的大小；位置仍使用固定点/厘米而非 Unity 随机数。
- 召唤物不继承施法者的路径、目标或当前阻挡关系。它作为新单位在下一 Tick 激活后，按照当前主分支的普通单位规则重新索敌、移动、阻挡和攻击。

## 结算与终局规则

每个 Tick 的伤害和死亡先完成。若死亡会触发效果，必须完整结算该死亡效果队列及其连锁后，才允许进行胜负判定。

一旦该胜负判定确认战斗终局，该 Tick 不再执行自动技力恢复或定时技能施放，且后续 Tick 不再继续。这样既不跳过死亡效果，也不会因技力或新召唤物让已经结束的战斗延长。

若战斗未终局，才处理存活且已激活单位的自动技力恢复和定时能力施放。新 Spawn 在施放 Tick 记录，但从下一 Tick 才进入正常行动阶段。

## 主分支集成边界

1. 作者数据仍为单位/能力 JSON；Editor 生成器只读取、校验并生成运行时目录，绝不回写源 JSON。
2. 加载层将单位的能力 ID 与能力定义封存到纯 Core 输入。Core 不依赖 Unity、Resources、Spine 或系统随机数。
3. Core 为每条自动技能维护私有技力、施放次数和激活状态；动态单位使用稳定、战斗内唯一的 ID 和不可变创建快照。
4. 演出层只根据 Core 结果中的 Spawn 事件和不可变快照创建动态视图；它不猜测能力逻辑或改变战斗状态。
5. 复用当前主分支的目标选择优先级。技能接入不得改变现有攻击、阻挡、准备阶段、UI 生命周期或展示轨道的规则，除非由本能力所必需且有新增测试覆盖。

## 验证

- 单位与能力目录加载：5504 数据、空能力名、文案、技力配置、3 个 5504 的 1 格方形效果均被校验。
- Core：Tick 100/250、技能独立技力、终局时不施放、死亡效果先于终局、3 个 Spawn、固定点确定性位置、下一 Tick 激活、重新索敌和无递归召唤。
- 集成：动态 Spawn 可被当前主分支的战斗结果/演出轨道/工厂完整播放，Replay 不泄漏动态视图。
- 回归：现有 EditMode、PlayMode 和编译均通过；任何旧测试需要更新时，必须保持其原有玩家可见意图，而不能用删断言规避失败。

## 非范围

- 通用 Buff、沉默效果实现、手动技能、其他触发器、治疗、护盾和其他能力效果类型。
- 修改 Unity、Package、渲染管线、Input System 或玩家持久状态写回。
