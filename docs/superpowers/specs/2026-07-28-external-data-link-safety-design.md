# 外部数据与文件链接安全规则设计

- 日期：2026-07-28
- 状态：已由项目负责人确认规则范围
- 目标文件：`AGENTS.md`
- 事故背景：单位 Cost 自测在 Unity 管理的 `Temp/` 下创建了指向项目外 staging 的目录 junction；fixture 后续被清理时，外部目标内容被连带清空。

## 1. 目标

把本次事故转化为仓库级强制规则，防止测试、临时目录清理和递归文件操作通过 junction、symbolic link、hard link 或其他 reparse point 影响项目外数据、用户数据或原始事实源。

## 2. 规则位置

在 `AGENTS.md` 第 5 章新增独立小节“外部数据与文件链接安全”。不把规则缩成第 5.4 节中的单行审批项，以免外部数据只读、链接禁令、清理前检查和事后验证散落在不同章节而被遗漏。

## 3. 强制规则

1. 项目目录外的数据和用户提供的事实源默认只读。即使任务允许读取该路径，也不代表允许创建、修改、覆盖、移动或删除其中的内容；任何项目外持久写入仍需事先获得明确批准。
2. 禁止在 `Temp/`、`Library/`、`Logs/`、缓存、构建输出、测试临时目录或其他可能被自动/递归清理的位置，创建指向项目外路径、用户数据或原始事实源的 junction、symbolic link、hard link 或其他 reparse point。
3. 测试需要外部数据时，只能把最少必要文件复制到独立 fixture；fixture 不得链接原始目录，不得在原始文件上注入错误数据。
4. 对目录执行递归删除、移动或清理前，必须枚举其中的 reparse point，并解析每个链接的实际目标。只要存在目标位于预期清理根目录之外的链接，就必须停止操作并报告。
5. 使用外部数据完成测试后，必须以只读方式核对源目录的文件数量、必要文件集合和关键文件哈希或等价完整性指标。发现变化时立即停止后续任务并报告，不得继续运行更多测试。
6. 一旦外部数据受到影响，必须说明影响范围、因果链、已停止的操作、可恢复来源和需要用户批准的恢复步骤；不得静默修复或把受损数据当作有效输入。

## 4. 范围与非目标

- 本次只修改 `AGENTS.md` 的代理工作规范。
- 不新增守卫脚本、Unity 测试、Package 或外部依赖。
- 不自动修复或重建项目外 staging。
- 不改变现有第 5.4 节“项目外持久写入必须审批”的要求；新规则是对其补充和强化。

## 5. 验证

修改后执行：

1. `git diff --check -- AGENTS.md`；
2. 检查新小节包含“默认只读”“禁止链接”“复制最小 fixture”“递归清理前解析目标”“测试后完整性核对”“事故报告”六项；
3. 检查没有修改 `AGENTS.md` 其他既有规则；
4. 检查最终 diff 不包含无关文件。
