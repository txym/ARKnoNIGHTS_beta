# 商店单位基础部署 Cost 设计

- 日期：2026-07-28
- 状态：已由项目负责人逐段确认
- 范围：`docs/bonds/BONDS_SPEC.md` 当前 94 个商店单位
- 不在范围：5 个非商店召唤、后继或能力单位；单位 JSON、Unity 代码与资源

## 1. 目标

本轮为每个商店单位设计唯一的精英 0 基础部署 Cost `C₀`。

Cost 的首要作用是平衡同稀有度单位的实际战斗力差异，同时使相邻稀有度的 Cost 增长跟随相邻稀有度的战力增长。Cost 不能按原始战力纯比例无限增长；需要压缩高稀有度费用，避免玩家在赤金和部署 Cost 都接近耗尽时，因为阵容稀有度路线不同而出现过大的等效战斗实体数差距。

当前 `5503=12` 与非商店 `5504=4` 都不是本轮锚点。94 个商店单位使用同一模型重新定价；已从 BONDS 删除的 `1000/1021` 不进入模型。

## 2. 已确认约束

1. 本轮只设计精英 0 基础 Cost `C₀`。
2. 精英 0/1/2/3 的部署 Cost 严格使用 `1/2/3/5 × C₀`，本轮不配置精英等级额外修正。
3. 精英 0/1/2/3 的战斗实体数同为 `1/2/3/5`，因此可见单位与战斗实体用同一“等效实体 Cost”口径校准。
4. 非商店单位没有独立部署 Cost；其战力按能力规则计入对应召唤者或母体。
5. R2—R6 档位中位 Cost 满足 `R6/R2 ≤ 4`。R1 独立进行同 Cost 团战校准，不受该比例约束。
6. 单位 Cost 为整数；R1 范围为 `2..40`，R2—R6 范围为 `5..40`。
7. R6 中位 Cost 的缩放目标约为 `28`。
8. Cost `31..40` 只用于少数极端单位，目标不超过 8 个；每个超过 30 的单位必须在分析报告中记录理由。
9. 相邻稀有度的中位 Cost 单调不下降；强低稀有度与弱高稀有度单位可以在边缘出现 Cost 重叠。
10. 羁绊稀缺性不作为主要加价项。Cost 主要由单位自身战斗体、已确认能力以及这些能力的多实体表现决定。
11. 召唤、能力、伤害类型和行为只使用 BONDS、SPEC 和本任务中项目负责人明确确认的内容，不从原作补入 BONDS 未写明的能力。

## 3. 数据来源与解析

### 3.1 名单与稀有度

`docs/bonds/BONDS_SPEC.md` 的“商店单位（94）”是本轮唯一名单。解析必须得到：

- 94 个商店 TypeId；
- 94 个唯一 TypeId；
- 5 个非商店 TypeId 不进入 Cost 表；
- 每个商店 TypeId 能在 BONDS 中解析到唯一名称和稀有度。

### 3.2 基础面板

每个商店单位从以下目录读取：

`G:/ARKnoNIGHTS_tools/spine-fetcher-output-variants-20260725/staging/<基础目录>/`

基础面板读取 `unit-levels.json` 中唯一的 `level: 0`。读取字段为：

- `maxHitPoints`
- `attack`
- `defense`
- `magicResistance`
- `attackIntervalSeconds`
- `moveSpeedMetresPerSecond`
- `lifeDeduct`

攻击类型优先读取同目录 `unit-source-v1.json` 的 `damageType`。基础攻击有效间隔继续使用已经确认的：

`effectiveAttackInterval = attackIntervalSeconds × 0.5`

基础目录缺失、`level: 0` 缺失或重复、数值非法、TypeId 不一致时，导出必须失败，不允许静默回退。

`1322` 保留 BONDS 已确认的反向映射：`1322_wdgyht_2` 是默认/E0，`1322_wdgyht` 是 E2。不能根据目录后缀覆盖该机制事实。

项目外 staging 始终只读。测试前后必须对本次实际读取的全部 94 个商店基础目录、5 个非商店能力引用目录和 `1322_wdgyht` E2 证据目录中的两份 JSON 做路径、长度与 SHA-256 核对；当前最小输入集合应为 100 个目录、200 份 JSON。不得用 junction、symbolic link、hard link 或其他 reparse point 构造测试 fixture。

### 3.3 精英变体

存在 `_2`、`_3` 目录时，读取各自唯一的 `level: 0`，仅用于检查精英 Cost 倍率下的单位级效率异常。缺少变体时按现有精英继承规则使用最近的较低条目；缺少专用目录不代表不能精英化。

14. 能力输入中任何未识别或未消费的参数必须使导出失败，不能静默忽略。

## 5. 连续战力

### 5.1 基础输出与防守

使用 94 个商店单位的 E0 面板构造同批环境：

- 不可被攻击的无人机不进入防守样本；
- 没有普通攻击的单位不进入普通攻击样本；
- 物理、法术和真实伤害按 SPEC 的正式伤害公式计算；
- 输出轴使用攻击者面对有效防守样本的中位实际 DPS；
- 防守轴使用防守者面对有效普通攻击样本的中位承伤时间；
- 对输出和防守轴分别按全体有效样本的 P5/P95 做 Winsorize 裁剪，再计算档位中位数，避免单个极端面板决定整条曲线；未裁剪原值仍保留在 CSV 中。

令全体有效样本的输出和防守中位数分别为 `O_ref`、`D_ref`。普通战斗体的基础面板指数为：

`PanelPower_i = sqrt((O_i / O_ref) × (D_i / D_ref))`

几何组合使“把同一种基础单位数量增加 n 倍”在输出和总耐久同时增加 n 倍时，等效战力约增加 n 倍；不会把输出和耐久的乘积错误解释为 n² 个等效单位。

### 5.2 能力场景

能力不使用统一的文字档位直接乘系数，而是在少量固定场景中修改输出、防守或增加等效实体：

- 自身增伤、攻速、减伤、闪避、回复、自损和变身直接修改对应 20 秒场景的实际输出或有效承伤；
- 范围伤害记录命中 1/2/3 个目标时的结果，主评分使用中间场景，另外两项作为敏感度边界；
- 光环记录覆盖 1/3/5 个有效目标时的边际收益，主评分使用覆盖 3 个目标；
- 召唤按 20 秒内已确认的生成次数、召唤体面板、存活时间和目标价值计算，不为召唤体创建 Cost；
- 不可阻挡、直冲门、位移和不攻击单位使用路径压力、目标价值和存活场景，不用无意义的普通 DPS 冒充；
- 不可被攻击的无人机只使用支援、覆盖、持续时间、路线、沉默和多实体规则，不使用基础 HP/DEF/MR 抬高评分。

能力场景得到的输出、防守和等效实体贡献合并为单位连续战力 `P_i`。数据表必须分别保留基础面板指数、能力修正和最终 `P_i`，不能只输出一个无法审计的总分。

### 5.3 档位中位战力

对每个稀有度 `r`，计算：

`M_r = median(P_i | rarity_i = r)`

再对 `M_1..M_6` 做非递减单调回归，得到 `M̃_r`。该步骤只消除样本噪声造成的档位中位倒挂，不改变单位稀有度，也不强迫每个高稀有度单位强于所有低稀有度单位。

## 6. Cost 数学模型

### 6.1 R2—R6 压缩曲线

压缩指数为：

`α = min(1, ln(4) / ln(M̃_6 / M̃_2))`

若 `M̃_6 ≤ M̃_2`，说明战力评分或稀有度输入存在实质冲突，必须停止，不得用 `α=0` 或其他兜底伪造曲线。

以 R6 档位基准约 28 进行缩放：

`B_r = 28 × (M̃_r / M̃_6)^α, r ∈ {2,3,4,5,6}`

因此：

`B_6 / B_2 ≤ 4`

且相邻档位满足：

`B_r / B_(r-1) = (M̃_r / M̃_(r-1))^α`

这会保留相邻战力增长的相对结构，同时避免原始战力纯比例造成高稀有度 Cost 爆炸。

### 6.2 同稀有度单位修正

单位初始连续 Cost 为：

`C*_i = B_r × clamp((P_i / M̃_r)^0.6, 0.75, 1.35)`

其中：

- `0.6` 是同档战力差的压缩指数；
- `0.75..1.35` 把单个单位修正限制在档位基准附近；
- 修正后允许相邻稀有度边缘重叠；
- 初始整数 Cost 使用标准四舍五入，再限制到 `5..40`。

若超过 30 的单位多于 8 个，优先缩小同档上修正范围或统一降低顶端缩放，不按名单逐个任意降价。任何调整都必须重新运行分布和相关性检查。

### 6.3 R1 独立校准

R1 的模型初值为：

`B_1_initial = B_2 × (M̃_1 / M̃_2)^α`

R1 单位先按第 6.2 节生成初始 Cost，再使用轻量 R1 对 R2 同 Cost 团战求统一校准系数：

`C_R1_final = clamp(round(κ_1 × C_R1_initial), 2, 40)`

`κ_1` 在 `0.01..1.50`、步长 `0.01` 的离散候选中选择，不手工逐个修改 R1。若初始 Cost 已通过团战校准，`κ_1=1`。

R1 不受 `R6/R2 ≤ 4` 之外的 `R6/R1` 比例限制；其最终中位 Cost 由团战中的数量非线性决定。

## 7. 轻量 R1/R2 团战校准

团战校准只用于发现 R1 与 R2 的明显数量偏差，不实现完整 Battle Core：

1. 固定使用 `54/99/126/195` 四个部署预算；
2. 每个预算、每个档位各构造三种代表阵容：从该档最低 Cost 半区稳定轮转填充、从最接近档位中位 Cost 的单位稳定轮转填充、从最高 Cost 半区稳定轮转填充；同一阵容允许重复 TypeId，剩余预算小于该候选集最低 Cost 时停止；
3. 交换双方与目标顺序，避免单一先手或单一前排决定结果；
4. 使用聚合实际 DPS、有效 HP、身体数量、最低伤害、阻挡容量、死亡后继和已量化能力；
5. 按简化的集火—死亡—移除循环推进，不计算逐 Tick 寻路、动画或大量阵型枚举；
6. 每个预算形成 `3×3=9` 组 R1/R2 阵容配对并交换双方，共 `72` 场轻量对比；记录胜率、剩余实体数和剩余目标价值。

R1 对 R2 的代表性同 Cost 团战胜率落在 `40%..60%` 时通过。超出范围时调整统一 `κ_1` 后重算；不得为追求单一阵容 50% 而逐单位反复微调。

## 8. 精英效率复核

E1 的实体数和 Cost 同为 2 倍，基础效率理论上不变。

E2/E3 使用真实变体时，分别检查：

- `E2TotalPower / (3 × C₀)`
- `E3TotalPower / (5 × C₀)`

并与该单位 E0 的 `E0Power / C₀` 比较。异常增长只用于单位级 `C₀` 复核；本轮不改变精英倍率。若为了修正高阶效率而提高 `C₀` 会使 E0 在同稀有度中明显失真，则将其记录为精英成长风险，不用错误的基础 Cost 同时掩盖两个问题。

## 9. 赤金与单位数量复核

单位售价继续等于稀有度。使用现有经济文档的累计赤金压力点：

`34 / 76 / 126 / 184 / 250 / 324`

对不同稀有度混合阵容计算：

`N(G,K,r) = min(floor(G/r), floor(K/C_r))`

该计算只检查 Cost 曲线是否再次放大赤金已经产生的单位数差异。永久 Cost 收入尚未确认，因此使用参数化 `K` 网格报告结果，不把任何 Cost 收入曲线写成正式规则。

1. 商店名单恰好 94 个且唯一。
2. Cost 表恰好 94 行，TypeId 集合与商店名单完全一致。
3. 非商店单位没有 Cost。

10. 每个 Cost 超过 30 的单位都有量化或已确认机制理由。
11. 所有未量化能力只出现在风险列，没有借用未确认原作参数。
