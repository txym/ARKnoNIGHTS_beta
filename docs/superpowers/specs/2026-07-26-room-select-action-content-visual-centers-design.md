# Room Select 横条图标与文字视觉中心校准设计

状态：用户已确认设计方向。

## 目标

在不改变 Home 页两条主操作横条背景 Rect 的前提下，分别校准“创建同盟”和“加入同盟”的图标与文字，使它们的可见像素边界和视觉中心匹配参考图 9。

本轮只调整横条内部图标与文字，不修改创建房间、发现房间、房间号预填、加入房间或 LAN 协议行为。

## 固定锚点

1920×1080、屏幕左上角为原点时，两条背景 Rect 保持为：

| 横条 | X | Y | Width | Height |
| --- | ---: | ---: | ---: | ---: |
| 创建同盟 | `1154` | `453` | `717` | `99` |
| 加入同盟 | `1154` | `876` | `717` | `99` |

背景贴图、点击 Rect、渲染顺序以及其他装饰与横条的遮挡关系均保持现有已验收行为。

## 问题定义

现有实现把图标完整 Sprite Rect 的几何中心放到统一锚点，但图标包含不对称透明留白：

- `create_icon.png` 的 Alpha 可见区域和质心略偏左上；
- `join_icon.png` 的 Alpha 可见区域明显偏左，视觉中心与完整贴图中心相差更大。

因此两个图标不能共享同一尺寸和锚点。文字当前宽高已接近参考图，主要偏差来自 Create/Join 使用了相同的左边距和垂直对齐。

## 选择的实现方式

采用每条横条独立的局部布局参数：

- Create 和 Join 分别拥有图标尺寸、图标局部中心、文字左边距和文字垂直偏移；
- 保留素材原图，不裁剪透明边缘，不生成替代位图；
- 不在运行时读取纹理像素或计算 Alpha 质心；
- 字号初始保持 `38`，只有截图证明字形尺寸仍超过验收误差时才允许小幅调整。

这样既能按可见像素校准，又不会引入纹理可读性要求、运行时分析或新的派生素材。

## 参考目标

以下坐标均以各自 `717×99` 横条裁剪图的左上角为原点，目标是参考图 9 中深色图标与文字的可见像素边界：

| 内容 | 目标可见边界 |
| --- | --- |
| 创建图标 | `x=47..82, y=25..61` |
| 创建文字 | `x=109..256, y=28..59` |
| 加入图标 | `x=47..90, y=20..69` |
| 加入文字 | `x=104..253, y=31..64` |

实现参数以这些可见边界为验收依据，而不是以 Sprite Rect 或 Text Rect 的几何中心为依据。由于 Unity 字体抗锯齿可能产生低 Alpha 边缘，自动测量使用固定的深色像素阈值，并在参考图和实际图上使用同一阈值。

## 代码边界

修改范围限定为：

- `LanLobbyView` 中 Create/Join 横条内部图标与文字布局；
- 对应的布局或 PlayMode 测试；
- 局部截图比对脚本、差异结果和素材使用报告中与本轮校准直接相关的部分。

不得修改：

- 两条背景横条 Rect；
- Room 页 UI；
- 房间创建、发现、加入及局域网通信逻辑；
- 素材文件内容、导入来源或 `.meta` GUID；
- 横条之外装饰物的布局。

## 验证

1. 自动布局测试确认两条背景 Rect 完全不变，并确认 Create/Join 使用独立图标和文字布局参数。
2. 运行相关 EditMode/PlayMode 测试，确保横条点击与 LAN 房间闭环无回归。
3. 用真实 1920×1080 Player 截取 Home 全屏图。
4. 分别生成 `home-create-action` 和 `home-join-action` 局部裁剪，与参考图 9 对比。
5. 自动报告每个图标和文字的参考可见边界、实际可见边界、视觉中心偏差和尺寸偏差。

通过标准：

- 两条背景 Rect 的位置和尺寸偏差为 `0 px`；
- 每个图标和文字的可见像素中心在 X、Y 方向的偏差均不超过 `1 px`；
- 每个图标和文字的可见边界宽高偏差均不超过 `2 px`；
- 其他装饰不遮挡横条，也不拦截横条点击；
- 素材报告继续明确列出原始素材路径、Unity 导入路径、Sprite 名称以及 Unity 文字，不把文字误报为位图素材。

若字体栅格化使字号 `38` 无法同时满足中心与边界尺寸要求，允许为 Create/Join 分别小幅调整字号并重新校准；在全部误差达到上述标准前仍记为未通过。不得通过移动背景横条掩盖内部内容偏差。
