## 1. 评分口径

### 1.1 输出与防御

- 物理普通攻击使用 CSV 的实际候选互测结果。表内列出中位 DPS、中位 TTK、P75 防御层 TTK 和 `PhysicalFloorTargetRate`；保底率越高，越不能把原始攻击力直接视为有效输出。
- 法术普通攻击不与物理攻击按原始攻击力混排。表内 `MR0/20/32.5/50` 分别对应方法文档的 P25/P50/P75/P90 法抗层，列出按法术公式得到的 DPS；其伤害保留率分别是 `100%/80%/67.5%/50%`。
- `MedianIncomingTtdSeconds` 只表示 CSV 基础面板在普通攻击互测中的中位承伤时间。回复、闪避、减伤、半血变身、自损和相邻实体加防在各单位行中另列，不能用基础 TTD 代替。
- 无人机按 BONDS 的现行规则不可被攻击，基础 HP、DEF、MR 和 CSV TTD 不进入稀有度判断；只评价光环、路线、持续时间、沉默、覆盖和部署 Cost 语义。
- 未强制任何档位数量。部署 Cost 留作同稀有度内的后续平衡轴，不用于把高访问性或规则改变单位压入错误档位。

### 1.2 能力预算档

- `none`：没有特殊能力，稀有度完全由基础战斗体和冲家价值承担。
- `minor`：一次性或低幅度线性收益，通常不能单独成为阵容核心。
- `moderate`：能稳定改变一项输出、生存、阻挡或范围收益，但影响仍局部且可预测。
- `major`：显著改变局部交战、产生高价值召唤/范围伤害，或在精英多实体下形成明显放大。
- `rule-changing`：绕过常规交战、改变全局单位/目标经济，或对整场阵型和规则状态产生关键影响。

表内“能力模型”固定按 `触发；持续；目标；叠加；沉默；实体` 顺序记录。BONDS 未写明可沉默时记为“未声明”，不推断为可沉默或不可沉默。所有常规可精英单位按方法文档的 E0/E1/E2/E3=`1/2/3/5` 个战斗实体回测；缺少 `_2`/`_3` 外部模型不取消该规则。一个可见单位仍只提供一次羁绊计数。

能力档与稀有度分开判定；`rule-changing` 不自动等于稀有6。低面板、低目标价值的规则入口仍可处于低稀有度，稀有6还要求该规则具有终局规模。为避免仅凭措辞主观分类，本轮对 `rule-changing` 使用以下可复核门槛，满足任一项即可：

1. **越过正常交战**：不可阻挡/位移越线是永久状态，或能在同一场战斗中重复触发且没有“一次性”上限。仅影响自身、全场只触发一次、持续不超过2s的越线不进该档；例如 `10001` 的1.5s一次性窗口仍为 `moderate`，而永久不可阻挡的 `1008/1026/1333` 与每三击重复位移的 `1322` 为 `rule-changing`。
2. **全局状态或递归规则**：直接改写多名友军的共享状态、使用全场共享计数/上限，或召唤体能继续产生召唤体。`1121` 的友军解放和 `2031/2033` 的共享帽递归属于此项。
3. **无帽实体/目标经济**：权威规则给出完整执行流程且没有设置共享上限，单个E0实体在开战20s内可净增加至少6点目标价值。`5503` 的 SPEC 在 Tick100/250/400 共生成9个目标价值1的 `5504`，且该完整流程没有共享帽，满足此项。若召唤频率或上限未知，则不能无条件套用此项。
4. **不可反制的持续多目标改写**：效果来源不可被攻击，且持续把覆盖区敌方攻击频率至少降低50%，或按玩家选点同时改变两项以上关键防守轴。该门槛覆盖 `1042` 与 `1146`；单轴的 `+300 DEF`、`+30 MR` 光环仍为 `major`。

`10077` 只有“初始SP3、需求5”，BONDS 没有SP回复速率或共享上限。当前证据只支持 `major`：本轮暂列稀有4。若后续权威规则证明单个E0终端在20s内至少施放6次且无共享帽，则升级为 `rule-changing` 并回测稀有5；若20s内少于6次或存在低共享帽，则维持 `major`/稀有4。该条件结论不借用 `5503` 的全局SP规则。

### 1.4 技能减伤与同类场景重放

物理技能同样经过 `max(原始技能伤害-DEF, floor(原始技能伤害×5%))`，法术技能和无来源法术反击同样经过目标MR。使用当前79个可攻击防守样本重放得到：

### 7.1 地区清单快照与计算口径

本节解析 2026-07-29 当前 `docs/bonds/BONDS_SPEC.md` 的 `# 按地区组织的单位` 章节，并使用该文件当前稀有度。本轮乌萨斯新增 `1078/1080/1081/1083`，整合运动当前新增 `1014/1031/1039/1502`；同期加入过的 `1076` 已删除，`1502` 是由错误的 `1302 弑君者` 校正而来。用户已移除地区间重复归属，本节不再沿用旧版的跨地区双计规则。

解析和交叉规则如下：

1. `# 按地区组织的单位` 下每个 `##` 标题都视为一个待比较地区，共8个；地区章节不再嵌套种类标题。地区范围内所有以十进制 ID 开头的详细条目或跨地区引用先在该地区内去重。
2. 只有属于当前94个商店单位且有唯一最终稀有度的条目才能计入。`PendingRemoval`、`NonShop` 和本轮删除项均不计入。
3. 同一个商店 TypeId 出现在两个地区视为清单错误，不再双计。当前81个有地区归属的商店单位全局唯一；`1043/1044/1061/1062` 当前只属于整合运动。
4. 对地区 `R`，`N(R,r)` 是最终稀有度为 `r` 的合法成员数；`N(R)=ΣN(R,r)`，`W(R)=Σ[r×N(R,r)]`，`A(R)=W(R)/N(R)`。
5. 若 `N=0`，则 `A` 显示为 `—`，不伪造为0，也不参加 `A` 中位数或排名。当前8个地区都满足 `N>0`。
6. 中位数先升序排列；偶数项取中间两值的算术平均。本轮地区同侪中位数为 `N=9.5`、`W=33.5`、`A=3.5278`。表内有符号差值统一为 `地区值−同侪中位数`。
7. `W`、`A` 都按降序使用标准竞赛排名：`名次=1+严格大于本地区值的地区数`。相同值共享名次，后续名次相应跳号。
8. `W/A` 是比较用信号，不是配额。`W` 低而 `A` 高，优先说明总量少；`W/A` 都低，才说明高稀有骨干不足；`W` 已高而 `A` 略低，通常是名单较大造成的密度稀释，不自动要求补R6。早期可用性单看 `R1+R2`。

当前萨尔贡、阿戈尔各有1个R6，叙拉古有2个R6；其余地区没有R6。R6不是地区配额，不能因为某地区 `R6=0` 就直接空降一名R6。仍有13个 Retained 单位尚未列入任何当前地区：`1017/1042/1355/2043/2046/5503/10001/10004/10005/10006/10073/10077/10078`；本轮不替用户补地区，所以它们不影响地区指标。

### 7.5 当前召唤单位空引用审计

当前运行时真正接入的召唤链只有 `5503 → SUMMON_JELLY_MINIONS → 5504`。生成的能力目录包含1项召唤能力，生成的单位目录只有 `1000/5503/5504` 三种类型；BONDS 中规划的 `1137/1138/1277/1433/1434/2033/10002/10073` 等召唤或后继体尚未进入运行时单位目录，不能据文档描述视为已经实现。

现有链路没有发现可由合法数据触发的空引用：

1. `BattleInputFactory.TryCreate` 在构造 `BattleInput` 前拒绝空能力、空 `SummonEffect`、未知召唤 TypeId、非正数数量/生成边长，以及单位引用的未知固有能力。`BattleInput` 构造器为 `internal`，正常准备阶段和数据加载器均走该工厂；因此 `BattleRunner.CastSummonAbility` 虽直接解引用 `SummonEffect` 并索引召唤类型，仍受已验证输入不变量保护。
2. Core 生成动态单位时立即创建非空快照、写入快照索引并发出 Spawn；Presentation 编译器对缺失或不匹配快照返回 `track.spawn.snapshot.missing/mismatch` 诊断，播放控制器也会拦截工厂失败或空 View，不继续解引用。
3. 当前 `5504` 项目源明确为 `canBlock=true`、`blockCapacity=1`，模型、默认 Prefab、SkeletonData、头像和生成目录绑定均存在；当前源目录与 Player-safe 单位目录的5504核心数值一致。

结论是：**当前已实现的 `5503→5504` 召唤链没有发现空引用缺口；未实现的文档召唤物会因未知 TypeId 在输入校验阶段失败，而不是在战斗中生成后空引用。** 后续接入其他召唤物时，必须先补齐单位目录、表现资源与能力定义，并复用未知类型、动态快照和真实 View 三层回归；不得只在 BONDS 中写入 ID 后直接引用。

2026-07-29 的专项验证为：召唤输入、Tick100/250生成、确定性动态ID与快照、下一Tick激活索敌、动态Track诊断和回放状态共 `17/17` 个 EditMode 用例通过；真实5504表现、暂停/变速、观察切换、死亡清理与 Replay 共 `10/10` 个 PlayMode 用例通过，两份日志均未命中 `NullReferenceException`、未处理异常或C#编译错误。另一次覆盖整个 `BattleCoreEditModeTests + BattlePresentationEditModeTests` 的宽回归为 `78/80`：失败项是目录生成测试仍读取已经不存在的旧路径 `Assets/GameData/Units/Json`，分别停在“未知召唤类型生成器诊断前置路径缺失”和“读取1000旧源文件失败”；这不是5503→5504运行时空引用，但表示当前全量EditMode仍非全绿，需由单位数据目录迁移任务修正测试入口。

这张表体现了当前物理减算的一击线：DEF从300跨到800会让大量物理攻击跌入保底，所以同样1000秒TTD所需HP从约16.7万骤降到2.4万。MR没有“堆过阈值突然免伤”的同等效果，不能把高MR当作高DEF的等价替代。候选仍需用实际伤害类型 population 复算，尤其要检查法术和真实伤害尾部。

**均衡高面板的可执行下界：**

- 输出端若为物理，有效间隔 `0.75/1.0/1.25/1.5/2.0/3.0s` 时，达到600中位DPS所需ATK约为 `750/900/1050/1200/1500/2100`；法术对应约 `575/750/950/1125/1500/2250`。
- 生存端达到750秒中位TTD的最低示例约为 `HP125000/DEF300/MR20`，或 `HP18000/DEF800/MR35`；DEF继续提高到1200—3000时，在当前中位攻击 population 下仍大致需要HP18000。
- 因而一个没有特殊机制的典型均衡R6下界可以是：物理 `HP18000/ATK900/DEF800/MR35/有效间隔1.0s`，或法术 `HP18000/ATK750/DEF800/MR35/有效间隔1.0s`。这两个例子只表示刚过双门，不能据此复制成统一R6模板。

### 8.3 有特殊机制时最低需要什么

特殊机制可以替代与其直接相关的面板轴，但不能用一句“规则改变”免检：

1. **可正常攻击和承伤的机制体**：至少在一个主动轴达到当前R4中位，即中位DPS≥175或中位TTD≥230s；另一轴只有在机制明确使其无意义时才可豁免。
2. **周期触发体**：若效果不是死亡触发，E0本体在当前中位环境中应至少存活 `max(20s, 3×首次触发时间)`，保证机制不是理论存在、实战来不及运行。
3. **不可攻击/不可被近战选中的空中体**：可以豁免HP/DEF/MR/TTD，但机制必须达到终局规模；“不会被近战打到”本身只是一项生存机制，不单独构成R6。
4. **不攻击的支援体**：可以豁免DPS，但必须提供不可由普通面板替代的终局效果，并有明确范围、持续时间、叠加、沉默和多实体规则。

机制本身至少满足以下一项，才足以支持空降R6：

- 持续、不可轻易反制地让多目标总输出或有效生存提高约50%以上；
- E0单体在开战20秒内净增加至少6点目标价值/战斗实体经济，且生成规则完整、没有低共享上限；
- 改写递归召唤、全场共享状态/上限、路径或越线规则，并在终局战斗中能重复或持续生效。

最终判定顺序固定为：**先按level0真实面板跑74/72互测 → 判断是否通过三条纯面板路线之一 → 未通过时只允许由已写清的特殊机制补足对应轴 → 再检查多实体精英化、阻挡、目标价值和400血冲家风险。** 现有R5极端值只能作为环境锚点，不能把素材库新单位“先放R5再修正”；新素材达到本节门槛即可直接作为R6候选。
