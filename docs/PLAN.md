# BONDS 单位能力实施计划

## 目标

在 `codex/bonds-unit-abilities` 独立工作树中，按最新
`docs/bonds/BONDS_SPEC.md` 实现单位战斗能力与动画事件。先完成特殊单位索敌，再按可独立验证的能力批次推进；每完成一个机制就更新
`docs/bonds/BONDS_IMPLEMENTATION.md`。

## 范围

- Battle Core 的索敌、攻击资格、阻挡资格、属性修正、触发器、伤害、召唤和状态生命周期。
- Core 事件、Presentation Track 与 Spine 播放之间的 Skill 动画数据流。
- v2 单位源、能力源及 Player-safe 运行时目录的必要接线。
- 不修改场景、Prefab、Package 或 Unity 版本。

## 已确认规则

- 权威战斗固定 `20 TPS`。
- 所有 Skill 动画按 `2×` 播放：源时长按
  `ceil(durationSeconds × 20)` 转为 Tick，有效占用为
  `(sourceTicks + 1) / 2`。
- Skill 不打断已经开始的 Attack；满 SP 时排队到攻击动画完整结束后的下一 Tick。
- 不明确且会影响玩家可见行为的能力不猜测；可查 PRTS 的先查，仍无法确定则跳过并记录。
- 使用聚焦 EditMode 回归，避免为每个数值能力重复运行全量 PlayMode 或 Windows 构建。

## 风险与约束

- 主分支正在重构单位数据；首批迁移期间
  `unit-catalog-v1` 与 `ability-catalog-v1` 字节冻结。
- 当前 v2 权威源只有 `1000`、`5503`、`5504`；旧目录不能表达不攻击且不阻挡单位。
- 冲家、玩家生命结算、沉默和完整 Buff 叠加顺序尚未形成 Core 闭环。
- 多段 Skill 动画需要对应单位资源导入后才能做真实 Spine 验证。

## 实施顺序

1. 完成不攻击、不可索敌、不可阻挡、直冲敌方门和静止行动的 Core 表达与测试。
2. 建立 Skill 事件、`2×` 时长换算、攻击期间排队和 Presentation 播放。
3. 在不改变冻结目录的前提下，建立独立技能动画目录。
4. 实现低耦合被动属性与持续生命变化。
5. 实现生命阈值、受击、攻击计数和死亡触发。
6. 实现范围、光环、溅射、反击、召唤与传送。
7. 每小时检查 `txym` 新提交，只同步已提交内容。

## 验证

- 每个机制批次至少运行覆盖该批次的聚焦 EditMode 测试。
- 数据生成器修改后运行目录生成与加载回归，并核对冻结目录哈希。
- 动画链修改后运行 Skill/Presentation Track 回归；真实资源完整接线后再运行最小 PlayMode 冒烟。
- 完成前检查最终 diff、编译日志、结构化测试结果和未验证项。

## 停止条件

- 用户指令、SPEC 或主分支已确认架构发生无法兼容的实质冲突。
- 需要升级 Unity/Package、引入第三方依赖或修改高冲突序列化资源。
- 同一阻塞点连续三次不同尝试仍无法推进。
