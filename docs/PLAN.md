# BONDS 单位能力实施计划

## 目标

在 `codex/bonds-unit-abilities` 独立 worktree 中，按当前主工作区
`docs/bonds/BONDS_SPEC.md` 的最新内容实现单位战斗能力与对应动画事件。
优先完成特殊单位索敌，再按可独立验证的能力批次推进。

## 范围

- Battle Core 的索敌、攻击资格、阻挡资格、属性修正、触发器、伤害、
  召唤和状态生命周期。
- Core 事件、Presentation Track 与 Spine 播放之间的技能动画数据流。
- `unit-elite-variants-v2`、能力源 JSON 和 Player-safe 目录的必要扩展。
- 每完成一个机制后更新
  `docs/bonds/BONDS_IMPLEMENTATION.md`。

不在本任务内实现羁绊人数统计、商店概率、完整玩家生命结算、多人同步，
也不修改场景、Prefab、Package 或 Unity 版本，除非某项单位能力的最小完整
闭环确实需要。

## 已确认的全局规则

- 权威战斗固定为 `20 TPS`。
- 所有 Skill 动画按 `2x` 播放。Core 使用
  `ceil(jsonDurationSeconds * 0.5 * 20)` 作为技能动作 Tick，向上取整以保证
  动画完整播放。
- 技能不得中断已经开始的攻击；死亡仍具有最高动作优先级。
- 不明确且会影响玩家可见行为的能力不猜测：可查 PRTS 的先查 PRTS，仍无
  法确定的跳过并记录。
- 测试采用精简的聚焦 EditMode 回归；每个批次结束再做一次相关程序集验证，
  不为每个数值能力重复运行全量 PlayMode 或 Windows 构建。

## 风险

- 主分支正在重构单位数据，可能修改 v2 源文件、目录生成器和目录 DTO。
- 当前主线只有 3 个 v2 单位源文件，BONDS 中多数单位尚不能完成真实目录接线。
- 冲家、玩家生命结算、沉默和完整 Buff 叠加顺序尚未在当前 Core 中实现。
- 多段 Skill 动画和状态切换动画需要单位资源导入完成后才能做真实 Spine 验证。

## 实施顺序

1. 扩展 Core 对“不攻击、不可索敌、不可阻挡”的表达与筛选，保持现有普通
   近战行为不变。
2. 打通非攻击单位与新目录数据的加载，不为尚未确认的冲家结算伪造胜负。
3. 增加 Skill 事件、2x 时长换算、攻击期间排队和 Presentation 播放。
4. 实现低耦合被动属性和持续生命变化。
5. 实现受击、生命阈值、攻击计数和死亡触发能力。
6. 实现范围、光环、溅射、反击、召唤与传送能力。
7. 每小时检查 `txym` 新提交；仅同步已提交内容，冲突时停止同步并记录。

## 验证

- 基线：`BattleCoreEditModeTests` 已于 2026-07-29 运行，
  `57 passed / 0 failed / 0 skipped`。
- 每个机制批次至少运行覆盖该批次的聚焦 EditMode 测试。
- 数据生成器修改后运行目录生成和目录加载回归。
- 动画播放链修改后运行聚焦 Presentation EditMode；有真实资源接线时再运行
  最小 PlayMode。
- 完成前检查最终 diff、编译日志和未验证项。

## 停止条件

- 规则与当前用户指令、SPEC 或已提交主分支发生实质冲突。
- 主分支同步产生无法机械解决的冲突。
- 需要升级 Unity/Package、引入第三方依赖、修改高冲突序列化资源或访问项目
  外事实源。
- 同一阻塞点连续三次有实质差异的尝试仍无法推进。
