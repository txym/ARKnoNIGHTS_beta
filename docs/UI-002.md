# UI-002：SampleScene 自动启动与待部署区正式 UI

## 角色

你是本 Unity 项目的准备阶段 UI 与场景接入 Agent。

你的职责是把 UI-001 的本地玩家状态自动加载到 `SampleScene`，并按 `UI_SPEC.md` 制作正式待部署区和 Cost 显示。UI 必须是玩家状态的只读投影；本任务不实现部署到战场或回合状态机。

本任务获准最小修改 `SampleScene.unity`、新增正式 UI 组件和必要的 UI Prefab，并调整旧调试对象的默认显隐。不得关闭整个 `BattleDemoRoot` 或破坏现有战斗 Demo。

## 任务背景

当前 SampleScene 的待部署 UI 仍是调试原型：`InitButton` 调用 `ButtonDebug` 扫描源 JSON，`VirtualSlotPanel` 固定 12 个等宽槽并在 `[ExecuteAlways]` 下改写 Panel 尺寸。它既不表示玩家持有的实例和堆叠，也不符合最大 13 槽、自然 `180×200`、头像裁切、选中扩展和精英化层级规则。

UI-001 应已经交付 Player-safe 自动加载、PlayerState、Cost=99 和按 Cost/type ID 排序的严格堆叠槽快照。本任务必须直接消费该快照，不再让 `UnitFactory.SpawnAll` 或场景中临时 GameObject 决定槽位内容。

现有 `BattleDemoUI` 是独立调试面板，但 `BattleDemoController` 与 Presentation 工厂位于同一个 `BattleDemoRoot`。禁用整个根对象会释放协调器并破坏后续 UI-004 接入。因此只能隐藏调试 UI 的 Canvas/GraphicRaycaster/CanvasGroup，保持控制器和视图工厂可用。

## 本任务目标

1. 在 SampleScene 加载时自动创建/加载 UI-001 的本地 PlayerState；不要求点击 InitButton。
2. 建立正式 HUD 根和待部署区根，生命周期、引用和初始化失败行为明确。
3. 用真实有序堆叠槽快照生成 0～13 个待部署槽，显示真实头像、Cost、精英化和 `X数量`。
4. 实现 UI_SPEC 已确认的自然/压缩布局、头像裁切、选中状态、选中上移和压缩模式等差宽度过渡。
5. 建立实时 Deployment Cost 面板，显示 PlayerState 当前可用 Cost，初始可观察值为 99。
6. 自动响应 PlayerState 版本/事件变化并重建或增量刷新槽位；UI 不保留第二份权威顺序。
7. 默认隐藏旧 InitButton、ShopPanel、FoldButton 和不属于正式流程的 ButtonTest；保留旧源码和 UnityEvent 供历史诊断。
8. 默认隐藏 BattleDemo 调试 UI，并通过可配置组合键显示/隐藏；不禁用 `BattleDemoRoot`。
9. 提供初始化状态和结构化错误输出，使加载失败时不会显示伪造槽位或默认 Cost。
10. 为布局数学和一条真实场景加载建立精简但有效的测试与人工检查清单。

## 已确认规则

- SampleScene 进入后自动加载本地玩家状态；InitButton 不再属于正式流程。
- UI 只负责呈现和发起后续命令，玩家状态是 Cost、单位和槽位顺序的权威来源。
- 待部署区最多 13 个严格堆叠槽；没有槽时不显示待部署区背景。
- 槽从左到右按 Cost 升序、type ID 升序；UI 不重新排序。
- 每个槽对应一个严格堆叠组；数量为 1 时也显示 `X1`。
- 头像来自 `Assets/Resources/ProfilePicture`，目标自然尺寸为 `180×180`，不得横向拉伸变形。
- 完整槽位自然尺寸为 `180×200`；参考分辨率为 `1920×1080`，其他尺寸按 UI_SPEC 比例换算。
- 自然总宽度不超过屏幕时整体靠右；超过时压缩铺满，最小槽宽为自然头像宽度的 `7/9`。
- 压缩只改变可见宽度，头像保持比例并裁切；选中槽恢复自然宽度，其他槽按 UI_SPEC 形成等差过渡。
- 同一时间最多选中一个待部署槽；再次点击当前槽取消选中；选择不改变数据顺序。
- 槽位视觉层级、Sprite 名称、精英化装饰和 Cost 位置以 UI_SPEC 为准。
- BattleDemo 调试 UI 可以默认隐藏并由组合键呼出；BattleDemo 控制器必须保持启用。
- 商店 UI 当前不实现，应默认隐藏。

## 实施要求

### A. 场景和初始化边界

1. 先以文本和 Unity Inspector 双重确认 SampleScene 的 Canvas、CanvasScaler、EventSystem、旧 Panel、BattleDemoRoot 及所有现有用户差异。
2. 建立单一自动启动入口，在 Awake/Start 的明确时机加载 UI-001 本地玩家状态，并把同一实例提供给所有正式 UI。不得让每个面板分别加载一份玩家数据。
3. 初始化成功输出稳定摘要：schema、player ID、Cost、区域数量、有序槽数量。失败输出结构化错误并保持正式 UI 空/错误态，不回退调用 `ButtonDebug.Debugbutton`。
4. 自动入口必须避免 Domain Reload 关闭时静态实例残留；退出 Play/场景销毁时取消订阅并清理运行时对象。

### B. 正式待部署 UI

5. 正式槽组件接收一个只读堆叠槽 ViewModel/快照，不自行访问 PlayerUnitCollection 内部数组。
6. 每个槽显示：真实头像、背景、头像覆盖、当前精英化等级图标/装饰、部署 Cost、堆叠数量和选中覆盖。
7. Sprite 只能按 UI_SPEC 已确认名称从现有图集引用：`StagingSlotBackground`、`StagingSlotSelectionOverlay`、`StagingSlotElite1Decoration`、`StagingSlotElite2PlusHighlight`、四个精英化图标、`StagingSlotHeaderHalfBackground`、`StagingSlotCostIcon`、`StagingSlotPortraitOverlay`。
8. 精英化 0/1/2/3 的互斥显示和 1/2+ 底部效果必须符合 UI_SPEC。未知精英化值由 UI-001 加载器拒绝，UI 不默默夹取。
9. 头像保持正方形和宽高比。压缩槽使用 `RectMask2D`、等价裁切或其他不改图像比例的方案；不得通过 Image 非等比缩放把头像压窄。
10. 跟随槽宽横向变化的背景/覆盖/装饰与保持固定尺寸的头像信息元素必须分层实现，不得把整棵槽层级统一缩放。
11. 数量文字固定显示 `Xn`，包括 `X1`。字体、字号和边距未确认，先选择项目已有字体和可读的最小样式，并在报告中标注待视觉确认；不得安装字体包。

### C. 布局和选择

12. 把 UI_SPEC 的布局公式封装为可测试的纯计算：0～13 槽、自然/压缩模式、右对齐、最小宽、选中上移、选中自然宽和等差过渡。
13. 总宽不得超过可用屏幕宽；槽顺序和 ViewModel 索引不因布局变化或选择而改变。
14. 屏幕/Canvas 尺寸改变时重新计算布局；不要使用 `Screen.width != slotSize * 12` 之类固定 12 槽判断。
15. 同时最多一个选中槽。点击新槽切换，再点当前槽取消。选择只改变表现和当前选择 ID，不从堆叠中移除单位、不扣 Cost。
16. 订阅玩家状态变化后，按最新有序槽快照刷新。若选中槽因数据变化消失，清除选择；若仍存在，使用稳定槽标识恢复选择。

### D. Cost 和旧 UI 显隐

17. 建立 UI_SPEC 第 6.2 节的 DeploymentCostPanel，按当前 PlayerState 显示可用 Cost；位置、尺寸、背景和图标遵循已确认比例。
18. 本任务不创建赤金值；可以为 UI-005 预留根节点，但不得显示虚构货币数字。
19. 在自动加载稳定后，把场景中的 InitButton、ShopPanel、FoldButton 和 ButtonTest 设置为默认不激活或移出正式 Canvas 的可交互路径。不要删除其脚本、Prefab 或 UnityEvent 源码。
20. `VirtualSlotPanel` 不再驱动正式 Panel。可将旧对象整体标记为 legacy/debug 并默认隐藏，避免 `[ExecuteAlways]` 继续改写正式布局。

### E. BattleDemo 调试面板

21. 保持 `BattleDemoRoot`、`BattleDemoController` 和 `MappedBattlePresentationViewFactory` 启用。
22. 默认只隐藏 `BattleDemoUI` 的可见 Canvas/CanvasGroup 和 GraphicRaycaster；隐藏时不得遮挡正式 HUD 或接收射线。
23. 提供一个序列化可配置的组合键，默认建议 `Ctrl+Shift+F10`，使用项目现有输入能力，不升级 Input System。显示时恢复可见和交互，隐藏时关闭交互。
24. 连续切换不得重复创建按钮、重复注册回调或重建 BattleDemoCoordinator。

### F. 序列化和收尾

25. 若使用 Editor 场景接线方法，应幂等：重复执行不会新增第二个 HUD 根、第二个自动启动器或重复组件。
26. 修改场景/Prefab 后检查序列化 diff、GUID、引用和 `m_IsActive`，确认没有无关 RectTransform、地图、相机或旧 Prefab 改动。
27. 只把实际验证过的架构和测试结果写入文档。
